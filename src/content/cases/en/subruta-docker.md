## Context

The server was already running a PHP application in production on native nginx and PHP-FPM. Lab-Reserva had to be published at `/lab-reserva` with the same domain and certificate, but without sharing the database, PHP or anything else.

## Problem

Putting it under a sub-path triggered three failures at once:

- Requests to `/lab-reserva/index.php` ended up in the **other** application's PHP-FPM.
- URLs and assets generated by Laravel came out without the prefix.
- The two applications' session cookies could overwrite each other.

## Diagnosis

- **nginx precedence:** the main site's regex `location ~ \.php$` blocks won over a plain prefix.
- **Laravel didn't know it was behind a proxy** with a prefix.
- **The compiled frontend** had its base path fixed at build time.

## Solution

- `location ^~ /lab-reserva/` on the host nginx, which beats the regex locations. It strips the prefix and forwards to the container with `X-Forwarded-Prefix`, which Laravel trusts through `TRUSTED_PROXIES`.
- The base path goes into the Docker build as an argument and becomes `ASSET_URL` for the Vite chunks and the base for the router and HTTP client.
- Isolated cookies with `SESSION_PATH=/lab-reserva` and their own session name.
- Everything plugs into the main site with a single `include`.

## Result

The two applications are independent: each has its own database, its own PHP and its own deployment cycle. The original site was not changed beyond that one line.
